# قرارداد عملیاتی ربات (Trading Contract) — نسخهٔ ۱۴۰۵/۰۸/۲۳

این سند «قرارداد» بین کارفرما و ربات است. هر بند آن با کد واقعی پشتیبانی می‌شود و
توسط `selfcheck_rules.py` هر روز راستی‌آزمایی می‌گردد. نقض هر بند = خطا.

---

## بند ۱ — قیمت سفارش باید دقیقاً همان قیمت محاسبه‌شده باشد

```
قاعده:
  ۱) قیمت و تعداد با «انتخاب کامل + تایپ» در فرم نوشته می‌شود
  ۲) مقدار فیلدها بلافاصله خوانده و با مقدار هدف مقایسه می‌شود
  ۳) تا ۳ بار تلاش مجدد تا فیلد دقیقاً همان عدد را داشته باشد
  ۴) اگر فیلد درست نشد → سفارش ارسال نمی‌شود (abort با price_field_mismatch)
  ۵) بعد از ارسال، قیمتِ ثبت‌شده در کارگزار خوانده می‌شود:
     - اگر با قیمت هدف اختلاف > ۰.۵ ریال داشت → سفارش از /Order/Delete لغو
       و یک بار با قیمت درست دوباره ثبت می‌شود
  ۶) نتیجه در خروجی: intended_price · placed_price · price_ok · mismatch
پیاده‌سازی: pw/flow.js
```

## بند ۲ — خرید با قدرت خرید واقعی

```
قاعده:
  ۱) ۰۸:۴۰ دقیقه: ورود، خواندن قدرت خرید (AccountBalance) و بررسی لیست شبانه
  ۲) اگر لیست نامعتبر یا قدرت خرید < ۶ میلیون ریال → ایمیل «آماده نیست»
  ۳) ۰۸:۴۵:۰۰ (ثانیهٔ ۱): ثبت سفارش‌ها با داده‌های همان لحظه
  ۴) قیمت: آخرین قیمت معتبر پنل/بازار (نه فایل کهنه)
پیاده‌سازی: scheduler.py (08:40 preflight · 08:45 order) · preflight.py · order_candidates.py
```

## بند ۳ — پنجرهٔ سفارش و پایش

```
۰۸:۴۶ تا ۰۹:۴۵ هر ۵ دقیقه: پایش سفارش‌های باز (order_monitor.py)
۰۹:۰۰ تا ۱۲:۳۰ هر ۳ دقیقه: پایش سود/ضرر (intraday_exit.py)
```

## بند ۴ — لغو و جایگزینی در ۱۰:۰۰

```
قاعده:
  ۱) هر سفارش باز با executed < qty = پرنشده
  ۲) لغو از مسیر واقعی POST /Web/V1/Order/Delete با آرایهٔ شناسه‌ها
  ۳) کاندیدای بعدی از candidates.csv یا reserve.csv سفارش می‌شود
  ۴) هر روز تکرار می‌شود (خودکار، بدون دخالت)
پیاده‌سازی: rebalance.py · cancel_orders.py
```

## بند ۵ — سهم مساوی نمادها

```
قاعده:
  ۱) هدف هر نماد = کل دارایی ÷ ۳ (کل دارایی = نقد + ارزش روز سبد)
  ۲) فقط نمادهای موجودی اولویت دارند (تکمیل کمبود)
  ۳) اسلات جدید فقط اگر نقد کافی برای یک سهم کامل باشد
  ۴) افران (صندوق درآمد ثابت) در محاسبهٔ سهم مساوی نیست
  ۵) خساپا کاملاً خارج از محاسبات و حلقه است
پیاده‌سازی: order_candidates.py (holdings-first) · rebalance.total_assets
```

## بند ۶ — انتقال سود به افران

```
قاعده:
  ۱) بعد از هر فروش موفق، اگر سود محقق شد:
     خرید «افران» به ارزش همان سود (منهای کارمزد)
  ۲) افران هرگز توسط ربات فروخته نمی‌شود
  ۳) این قاعده موقتی است تا اعلام لغو
پیاده‌سازی: profit_transfer.py (مشترک بین همهٔ مسیرهای فروش)
```

## بند ۷ — روزهای تعطیل

```
شنبه تا چهارشنبه = روز معاملاتی · پنجشنبه/جمعه = تعطیل
در روز تعطیل: هیچ ورود، هیچ ایمیل آمادگی، هیچ سفارشی
پیاده‌سازی: market_cal.py
```

## بند ۸ — ایمیل

```
۰۸:۳۰ · ۰۸:۴۰ · ۰۸:۴۵: یک ایمیل آمادگی (هر کدام یک‌بار)

## بند ۹ — گزارش و حسابرسی

```
هر سفارش: orders_log.jsonl  (intended, placed, qty, message)

## بند ۱۰ — هیچ خطایی پذیرفته نیست

```
اگر هر بند شکسته شود:
  ۱) selfcheck_rules.py آن را FAIL اعلام می‌کند (۰۸:۲۵ و ۲۲:۰۰)
  ۲) ایمیل هشدار

     مگر شکست در بند ۱ یا ۲
```
