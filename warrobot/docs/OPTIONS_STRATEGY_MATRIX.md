# استراتژی معاملاتی بازار آپشن تهران — ماتریس شناخته/ناشناخته

## ۱) ماتریس اطلاعات

### شناخته‌ها (K)

| # | K | مقدار / منبع | اطمینان |
|---|---|---|---|
| K1 | قیمت پایانی روزانهٔ هر قرارداد (OHLC + حجم + ارزش) | TSETMC CDL — عمر کامل قرارداد | ✅ تست شد |
| K2 | فهرست ۶٬۲۳۶ قرارداد آپشن (۴٬۱۱۱ کال، ۲٬۱۲۵ پوت) | instruments.json محلی | ✅ |
| K3 | تاریخ معاملات هر قرارداد (شروع/پایان) | همان منبع | ✅ |
| K4 | نام قرارداد → دارایی پایه (حذف شمارهٔ انتهایی) | قاعدهٔ نام‌گذاری | ⚠️ تقریبی |
| K5 | بازار آپشن: پیش‌گشایش ۰۸:۴۵–۰۹:۰۰، معاملات ۰۹:۰۰–۱۲:۳۰ | تجربهٔ بورس تهران | ✅ |
| K6 | حد نوسان قیمت آپشن: بر اساس حدود نماد پایه و نه سقف ساده | دانش بازار | ⚠️ نیاز به تأیید |
| K7 | نقدشوندگی پایین اکثر قراردادها (حجم صفر در بسیاری از روزها) | تجربه | ✅ |
| K8 | کارمزد معاملات آپشن و مسیر ثبت سفارش در کارگزار | تجربهٔ ربات | ✅ |

### ناشناخته‌ها (U)

| # | U | چرا مهم است |
|---|---|---|
| U1 | قیمت اعمال و سررسید هر قرارداد | بدون آن نمی‌توان in/out-of-money و greeks را حساب کرد |
| U2 | نرخ بی‌ریسک روزانه (بازده اوراق) | لازم برای IV و ارزش اختیار |
| U3 | نوسان ضمنی تاریخی (IV) | میدان تصمیم اصلی آپشن |
| U4 | تاریخ دقیق فهرست شدن/منقضی شدن قرارداد | برای جلوگیری از look-ahead |
| U5 | نقدشوندگی واقعی (عمق سفارش) در گذشته | برای واقع‌گرایی بک‌تست |
| U6 | تغییرات قاعده/توقف‌های بازار در بازهٔ چندساله | استثنائات |
| U7 | گریکس تاریخی | فقط با محاسبهٔ خودمان (از K1 + U1,U2,U3) |

### راه‌حل ماتریس

```
U1 را از نام قرارداد و/یا کدال/TSE بازسازی می‌کنیم
U2 را از بازده اوراق دولتی تخمین می‌زنیم (نرخ ثابت فصلی)
U3 و U7 را خودمان با Black-Scholes محاسبه می‌کنیم (به دادهٔ خارجی نیاز ندارد)
U4 را از اولین/آخرین تاریخ موجود در سری قیمت می‌گیریم
U5 را با فیلتر نقدشوندگی (حجم > 0) در بک‌تست لحاظ می‌کنیم
U6 اثرش را با گزارش «دوره‌های استثنا» جدا می‌کنیم
```

## ۲) انتخاب روش: **تکنیکال** (نه بنیادی)

دلیل صریح:
```
بنیادی در آپشن تهران تقریباً بی‌معناست:
  - دادهٔ بنیادی برای خود قرارداد وجود ندارد (قرارداد، دارایی واقعی نیست)
  - بنیادیِ دارایی پایه هم فقط با تاخیر و نویز در دسترس است
  - و مهم‌تر: هیچ دادهٔ صورت‌های مالی روزانه‌ای در دسترس نیست

پس تنها روش قابل دفاع: تکنیکال روی سری قیمت آپشن + دارایی پایه
```

## ۳) فرضیهٔ استراتژی (نسخهٔ ۱)

**«مومنتوم قرارداد با فیلتر نقدشوندگی و محدودیت زمانی»**

```
هر روز (بعد از بستن بازار):
  ۱) فقط قراردادهایی که حجم ۵ روزه > ۰ دارند (نقدشونده)
  ۲) مومنتوم ۵ روزه قرارداد مثبت و بالای میانهٔ بازار آپشن
  ۳) ورود در قیمت بستهٔ روز، خروج بعد از ۳ روز یا با حد ضرر ۸٪
  ۴) حداکثر ۳ قرارداد همزمان، هرکدام یک‌سوم سرمایهٔ تخصیصی
  ۵) کال فقط (پوت‌ها جدا ارزیابی می‌شوند)
```

فرضیهٔ رقیب (برای آزمون):
```
B) بازگشت به میانگین: خرید افت ۳ روزهٔ شدید در قراردادهای نقدشونده
C) مومنتوم دارایی پایه: خرید کال دارایی‌هایی که دارایی پایه‌شان در ۵ روز اخیر مثبت بوده
```

## ۴) معیارهای پذیرش (پیش از دیدن نتیجه تعریف شد)

| معیار | حد پذیرش |
|---|---|
| بازده کل چندساله | > صفر و > بازده اوراق |
| نسبت سود/ضرر | > ۱.۳ |
| حداکثر افت سرمایه | < ۲۵٪ |
| تعداد معاملات | > ۲۰۰ (برای معناداری) |
| پایداری سالانه | در ≥ ۷۰٪ سال‌ها مثبت |
| حساسیت به پارامتر | تغییر ±۲۰٪ پارامترها، بازده مثبت بماند |

## ۵) دام‌های بک‌تست که از تجربهٔ ربات بورسی می‌آوریم

```
۱) look-ahead: سیگنال روی دادهٔ روز t، اجرا در t+1
۲) نقدشوندگی: فقط حجم واقعی همان روز، با سهم حداکثر ۱۰٪ حجم
۳) کارمزد: حداقل ۰.۵٪ رفت‌وبرگشت
۴) قراردادهای منقضی: خروج اجباری قبل از سررسید
۵) قیمت‌های تکراری/صفر: حذف روزهای بدون معامله
۶) survivorship: استفاده از همهٔ قراردادهای تاریخچه، نه فقط فعال‌ها
```
