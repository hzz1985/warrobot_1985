# دانش کارگزاری — آنچه تا امروز یاد گرفتیم (WarRobot)

هر مورد با شاهد اجرایی تأیید شده است. این سند مرجعِ رفتار ربات در برابر کارگزار است.

## ۱) مرورگر و اتصال

| موضوع | یافته |
|---|---|
| پورت اشکال‌زدایی ۹۳۳۳ | روی **پروفایل اصلی کروم باز نمی‌شود** (محدودیت کروم ۱۳۶+). فقط با `--user-data-dir` غیرپیش‌فرض باز می‌شود. |
| راه‌حل پایدار | **Playwright** با `channel: "chrome"` + پروفایل اختصاصی `state/pw-profile`. نیازی به دانلود مرورگر ندارد. |
| کروم همراه Playwright | دانلودش از شبکه مسدود است (`playwright install chromium` شکست می‌خورد). |
| نشست | **بین دو اجرا باقی نمی‌ماند**؛ ورود و سفارش باید در **یک نشست** انجام شوند. |
| ناوبری | هر `goto`/reload بعد از ورود، نشست را باطل می‌کند. فقط **کلیک داخل SPA** مجاز است. |
| رفرش ۰۸:۴۰ | یک reload عمدی، نشست مرده را به صفحهٔ Login می‌برد تا ورود خودکار اجرا شود. |

## ۲) ورود

- کپچا: ۴ رقم، تصویر data-URI با اندازهٔ ۱۴۵×۵۶.
- خواندن: `ocr/read2.js` (tesseract.js + پیش‌پردازش: خاکستری، آستانه، حذف خطوط نازک، بزرگ‌نمایی ۳×).
- دقت روی نمونه‌ها: ۶۵۹۱ · ۸۲۲۵ · ۹۷۰۰ · ۸۵۰۳ · ۴۱۵۶ · ۷۱۵۲ · ۸۸۳۷ · ۴۷۲۵ — همه درست.
- فرم ورود به‌صورت AutoFill پر می‌شود؛ **قبل از تایپ باید پاک شود** وگرنه «نام کاربری/رمز نامعتبر» می‌دهد.
- ارسال فرم: `submitForm()` (تابع خود سایت) یا کلیک روی `#main-form`.
- اعتبارنامه: `state/credentials.json` (از فایل MeiBourse.txt خوانده شد).

## ۳) تب درست برای سفارش

**`/Home/Default/page-1`** — همان صفحه‌ای که بعد از ورود باز می‌شود.
- فیلد تعداد `#send_order_txtCount` (عرض ۸۵) و قیمت `#send_order_txtPrice` (۷۹) همیشه موجودند.
- کادر جستجوی نماد `#txt_search` فقط بعد از کلیک روی عنوان **«دیده بان»** عرض می‌گیرد (۰ → ۱۶۶).
- تب‌های صفحه ۳/۴/۵ سفارش شرطی/دسته‌ای هستند و برای این کار بی‌فایده‌اند.

## ۴) بایند نماد

1. کلیک روی `span.lm_title` با متن «دیده بان»
2. `#txt_search` را `scrollIntoView` کن (وگرنه مختصات منفی می‌شود و کلیک اثر ندارد)
3. کلیک، تایپ نام، سپس رویدادهای کلید (`keydown/keypress/keyup`) — angucomplete فقط به کلید واکنش می‌دهد
4. کلیک روی نتیجه‌ای که متنش **دقیقاً** برابر نماد است
5. تأیید: `#fulltextContainer` باید نام نماد را نشان دهد

## ۵) قواعد قیمت و سایز (دو کشف کلیدی)

### قیمت
- قیمت باید **از پنل** خوانده شود (آخرین معامله/بهترین عرضه).
- قیمت محاسبه‌شده از فایل روزانه (`پایانی دیروز × ۱٫۰۳`) **رد می‌شود**:
  آباد با ۱٬۹۱۹ رد شد، با ۱٬۸۰۹ ثبت شد.
- اگر قیمت خارج از دامنهٔ مجاز باشد، پنل **هیچ پیامی نمی‌دهد** و API `OrderId=0` برمی‌گرداند.

### سایز
پاسخ `Accounting/Remain`:
```
RealBalance     : 3,319,229,960
BlockedBalance  : 2,965,972,938   ← سفارش‌های باز قبلی
AccountBalance  :   353,257,022   ← پول واقعاً آزاد
PurchasingPower : 3,319,229,960
```
- سایز باید بر اساس **AccountBalance** باشد، نه PurchasingPower.
- آردینه با ارزش ۱٫۰۸ میلیارد رد شد؛ با ۲۲۵ و ۴۵۰ میلیون ثبت شد.
- سقف تعداد هر بلیت: «آستانه حجم» (مثلاً آباد ۱٬۰۰۰٬۰۰۰ · آردینه ۳۰٬۰۰۰ · آواپارس ۳۰۰٬۰۰۰).

## ۶) API ثبت سفارش

```
POST https://api.meibours.ir/Web/V1/Order/Post
```
```json
{"IsSymbolCautionAgreement":false,"CautionAgreementSelected":false,
 "IsSymbolSepahAgreement":false,"SepahAgreementSelected":false,
 "orderCount":QTY,"orderPrice":PRICE,"FinancialProviderId":1,
 "minimumQuantity":0,"maxShow":0,"orderId":0,"isin":"IRO...",
 "orderSide":65,"orderValidity":74,"orderValiditydate":null,
 "shortSellIsEnabled":false,"shortSellIncentivePercent":0}
```
- `IsSuccessfull:true` + `Data.OrderId=0` یعنی **ثبت نشده** (رد خاموش).
- `IsSuccessfull:true` + `OrderId` غیرصفر یا پیام «با موفقیت در سیستم ثبت شد» یعنی **ثبت شده**.

### تاییدیه (Agreement)
- `Agreement/GetActiveAgreementList` → `[{AgreementId:2, «فرم پذیرش معاملات تحت احتیاط»}]`
- `Agreement/CheckAgreement` → `Data:0` (پذیرفته نشده) — **ولی مانع ثبت سفارش نیست** (با همین وضعیت سفارش ثبت شد).
- `Agreement/AcceptAgreement` با همهٔ شکل‌های پارامتر: «Sent id is not correct» → فعلاً لازم نیست.

## ۸) خطاهای شناخته‌شده و پاسخ

| نشانه | معنی | راه‌حل |
|---|---|---|
| `OrderId=0` بدون پیام | قیمت خارج از دامنه یا سایز بیش از پول آزاد | قیمت پنل + AccountBalance |
| «Unable to obtain driver for chrome» | مسیر Selenium قدیمی | استفاده از CDP/Playwright |

## ۱۰) محافظ ISIN (دور ۹)

پیش از کلیک روی «خرید»، فهرست کدهای ISIN موجود در صفحه خوانده می‌شود؛
اگر ISIN مورد انتظار پیدا نشود، سفارش کنسل می‌شود (هیچ کلیکی انجام نمی‌شود).
دلیل: نمادهای هم‌نام (مثل «آرمان») می‌توانند به نماد دیگری bind شوند و
سفارش با قیمت اشتباه ارسال شود. نمونهٔ واقعی: آرمان در پنل ~۱٬۰۵۰٬۰۰۰
ولی در فایل ۱٬۹۸۵.

خروجی هنگام خطا:
```
message: "isin_mismatch expected=IRO7ARMP0001 found=IRO1ABAD0001,..."
```

## ۱۴) باگ بحرانی بایند اشتباه (۱۴۰۵-۰۸-۱۸)

### مشاهده
درخواست سفارش «آبین» انجام شد، ولی پیام موفقیت برای «افران» آمد:
```
سفارش خرید افران1 با موفقیت در سیستم ثبت شد.
```
یعنی جستجوی پنل، نماد دیگری را bind کرده و سفارش برای نماد اشتباه ثبت شده است.
این خطرناک‌ترین باگ کل پروژه است: خرید نمادی که در کاندیداها نیست.

### رفع
در `pw/flow.js` بررسی «بایند دقیق» اضافه شد:
```
out.strictBind = normalized(boundText) === normalized(symbol)
if (!out.strictBind) -> abort با پیام bind_mismatch
```
هیچ کلیکی انجام نمی‌شود و سفارش ثبت نمی‌گردد.

### درس
- محافظ ISIN در DOM کافی نیست (برای نمادهای خارج از دیده‌بان پیدا نمی‌شود)
- معیار معتبر: متن نماد bind‌شده باید **دقیقاً** برابر نام درخواستی باشد
- و پیش از هر سفارش باید همین شرط بررسی شود
