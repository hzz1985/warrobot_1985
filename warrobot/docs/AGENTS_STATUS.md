# لایهٔ ایجنت‌ها — وضعیت نهایی (۱۴۰۵/۰۸/۲۷)

## ۱) مدل‌های محلی روی همین سرور

```
سخت‌افزار : ۴ vCPU · ۸GB RAM (~۲.۸ آزاد) · بدون GPU
Ollama    : 0.40.16 نصب و فعال (127.0.0.1:11434)
مدل       : qwen2.5:1.5b-instruct (۹۸۶MB)
حذف‌شده   : gemma2:2b (کیفیت فارسی بدتر، ۴۷ ثانیه برای ۸۰ توکن)
دیسک      : ۱۵.۵GB آزاد شد (حذف داده‌های معاملاتی بی‌استفاده)
```

### محدودیت اندازه‌گیری‌شده
```
پرسش فارسی → پاسخ انگلیسی/بی‌ربط
سرعت       → ۱۵ تا ۴۷ ثانیه برای چند ده توکن
```
**تصمیم:** متن فارسی با قالب آماده ساخته می‌شود (بدون LLM)؛
LLM فقط برای خلاصه/دسته‌بندی «انگلیسی» و «خارج از ساعت بازار» (با کش).

## ۳) حافظهٔ درس‌ها — «آموزش» ربات

```
state/lessons.jsonl
  هر درس: symptom → cause → fix → verify + tags
  اکنون: ۱۸ درس (کپچا، کروم یتیم، قیمت کهنه، TP لات‌محور، وب‌اپ کهنه، ...)
```

**چرخهٔ آموزش:**
```
۱) یک خطا رخ می‌دهد → a4_logs آن را در صف escalation می‌گذارد
۲) من (دیپ‌سیک) یا یک ایجنت آن را رفع می‌کند
۳) رفع به‌صورت یک «درس» با دستور verify ثبت می‌شود
۴) دفعهٔ بعد همان الگو در a4 به درس متصل می‌شود
   → دیگر به دیپ‌سیک نمی‌رسد
```

## ۴) صف escalation — تنها نقطهٔ تماس با دیپ‌سیک

```
state/escalation/queue.json
  فقط مواردی که هیچ قانونی جواب نمی‌دهد
  خلاصه + agent + زمان + جزئیات
  → یک فایل، نه ده‌ها پیام
```

## ۵) کاهش مصرف توکن (اجرا‌شده)

| اقدام | برآورد اثر |
|---|---|
| چهار ایجنت قانون‌محور برای ورود/پیش‌گشایش/وب‌اپ/لاگ | حذف ~۹۰٪ جلسات عیب‌یابی روزانه |
| کش SQLite پاسخ‌های LLM | ۴۰–۶۰٪ تکرار → صفر توکن |

## ۶) حالت کاهش‌یافته

```

```
