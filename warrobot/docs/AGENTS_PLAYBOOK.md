# Agents — دفترچهٔ راهنمای ساخت و آموزش ایجنت‌های محلی

> این فایل، تجربهٔ پروژهٔ WarRobot را به یک «فرآیند قابل تکرار» تبدیل می‌کند.
> هر پروژهٔ بعدی (یا تکمیل پروژه‌های قبلی) باید از همین الگو استفاده کند.

---

## ۱) قانون اصلی

```
هر کاری که یک «قانون if/else» می‌تواند انجام دهد  → هیچ مدلی، هیچ ایجنتی
هر کاری که یک اسکریپت محلی با تست می‌تواند انجام دهد → به معمار (دیپ‌سیک) سپرده نشود
معمار فقط: طراحی، کد اولیه، تصمیم‌های نادر، بازبینی کیفیت
```

### تصمیم درختچه‌ای (همیشه به همین ترتیب)

```
۱) آیا می‌توان با قانون قطعی حل کرد؟        → بله: اسکریپت پایتون (بدون LLM)
۲) آیا مدل کوچک محلی کافی است؟               → بله: Ollama (فقط خلاصه/دسته‌بندی، با کش)
۳) آیا مورد نادر و جدید است؟                 → صف escalation برای معمار
۴) آیا تصمیم انسانی لازم است؟                → ایمیل به مالک پروژه
```

---

## ۲) انتخاب مدل محلی — اول سخت‌افزار، بعد وظیفه

```
قبل از هر نصب، این‌ها را اندازه بگیر:
  RAM کل/آزاد · تعداد هسته · GPU/VRAM · دیسک آزاد

قاعدهٔ تجربی (CPU-only):
  ۰.۵B–۱.۵B  → ~۱GB RAM · فقط خلاصه/دسته‌بندی انگلیسی · ۱۵–۳۰ ثانیه
  ۲B–۳B      → ~۲GB RAM · مرز خطر با برنامه‌های دیگر
  ۷B+        → ~۵GB RAM + GPU · روی ماشین ۸GB/بدون GPU اجرا نکن
```

### درس واقعی این پروژه
```
qwen2.5:1.5b و gemma2:2b → پرسش فارسی را نفهمیدند
نتیجه: متن فارسی با قالب آماده (deterministic) ساخته می‌شود، نه با مدل کوچک
```

## ۳) آناتومی هر ایجنت (الگوی اجباری)

```
agents/<name>.py
  run(repair: bool = True) -> dict

  ۱) checks   : چند بررسی ساده که وضعیت را می‌سنجد
  ۲) actions  : اقدام‌های محدود و امن (حداکثر یک بار برای هر مرحله)
  ۳) report   : JSON در state/agents/<name>.json  (ok, at, escalate)
  ۴) verify   : بعد از اقدام، دوباره چک کن (بدون verify، اقدام معتبر نیست)
  ۵) escalate : اگر حل نشد، یک کلید کوتاه در صف بگذار
```

### مثال اسکلت

```python
def run(repair=True):
    out = {"agent": "aX", "at": now(), "actions": []}
    out["checks"] = {...}
    if repair and broken:
        out["actions"].append(do_fix())
        out["checks"] = verify_again()
    out["ok"] = all_checks_pass()
    if not out["ok"]:
        out["escalate"] = "short_reason"
    write_json(out)
    return out
```

## ۴) حافظهٔ درس‌ها (آموزش بدون fine-tune)

```
state/lessons.jsonl
  {symptom, cause, fix, verify, tags}

چرخه:
  خطا → a4 (تریاژ) → تطبیق با درس‌ها → اگر نبود: صف escalation
  رفع شد → درس ثبت می‌شود → دفعهٔ بعد همان الگو خودکار بسته می‌شود
```

**قاعده:** هر رفع، باید «دستور verify» داشته باشد؛ درس بدون راه سنجش، درس نیست.

## ۵) کاهش مصرف توکن (اجراشده و قابل تکرار)

| تکنیک | پیاده‌سازی |
|---|---|
| مسیریابی | rule → local model → architect |
| کش | SQLite روی هش(prompt) با TTL |
| دسته‌بندی | صف escalation به‌جای چت |
| خلاصه | حداکثر ~۸۰۰ توکن قبل از ارسال به معمار |
| قالب آماده | متن فارسی از template، نه LLM |

## ۷) نردبان ارجاع (Escalation)

```
۱) ایجنت خودش رفع می‌کند (repair)
۲) اگر نشد → صف state/escalation/queue.json  (برای معمار)
۳) اگر بحرانی بود (ورود/سفارش/سرویس) → ایمیل فوری به مالک پروژه
   پیام: «اول به معمار ارجاع شد؛ اگر تا پایان روز حل نشد وارد شو»
۴) حالت کاهش‌یافته: بدون Ollama و بدون معمار، سیستم معاملاتی متوقف نمی‌شود
```

## ۸) سطح مشاهده (بدون پرسیدن از معمار)

```
تب «ایجنت‌ها» در وب‌اپ:
  - وضعیت هر ایجنت (سالم/نیازمند بررسی)
  - صف escalation
  - تعداد و آخرین درس‌ها
  - وضعیت مدل محلی (فعال/قفل ساعت بازار)
```
